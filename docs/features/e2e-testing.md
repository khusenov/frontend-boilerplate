# End-to-end testing

> **Status:** Complete · **Layers:** outside layers · **Verified against:** `1c193c6`

## Purpose

The Vitest suite never loads the app a visitor downloads: it runs in jsdom or Node against stub
`HttpClient`s and MSW handlers whose payloads are written beside the code under test. Nothing in it
can therefore notice drift in the production bundle, in the route tree the Vite plugin generates or
in the wire contract — renaming `first_name` and `last_name` in the user DTO, its mapper and the
unit fixtures together leaves `npm run audit` green, because the code and its tests agree on a shape
the server never agreed to. The end-to-end harness closes that gap: Playwright drives a real
Chromium against the production build, and the API is answered inside the browser by stubs that
pin their own copy of the wire contract and may not import `src/`. It is a developer-facing
capability — npm scripts and a CI job run it, and the shipped bundle contains none of it.

## How it works

**Booting the app under test.** `npm run test:e2e` runs `playwright test`, which reads
`playwright.config.ts`. Before the first test, its `webServer` runs
`npm run build && npm run preview -- --port 4173 --strictPort` with `VITE_API_BASE_URL` set to
`API_PREFIX` (`/v1`) on top of the inherited environment. `npm run build` is
`tsc -b && vite build`: it type-checks the app, Node and end-to-end TypeScript projects, then builds
`dist/` in production mode — minified, with `import.meta.env` inlined, the route tree generated by
the TanStack router plugin, and both devtools panels rendering nothing. `vite preview` serves
`dist/` on port 4173, and Playwright waits up to 120 s for `http://localhost:4173` to answer; if
something already listens there, the run stops instead of reusing it.

**A fresh browser context per test.** Tests run in parallel (`fullyParallel: true`) in the single
`chromium` project (`devices['Desktop Chrome']`), each in a new browser context with `baseURL`
`http://localhost:4173`, `locale: 'en-US'` and `timezoneId: 'UTC'`, so no cookie, storage entry or
in-memory session carries over from another test.

**The network fence.** Specs import `test` and `expect` from `e2e/fixtures/harness.ts`, not from
`@playwright/test`. That `test` carries a `userStub` _fixture_ — Playwright's unit of per-test setup
and teardown — marked `{ auto: true }`, so it runs before every test body, including tests that
never name it. It creates a fresh stub with `createUserStub()` and registers three handlers on
`API_ROUTE_PATTERN` (`**/v1/**`) with `page.route`: the catch-all `reportUnhandledRequest`, then
`restoreSession`, then the user stub's `handle`. Playwright offers a matching request to the most
recently registered handler first, and each handler either fulfils the request or calls
`route.fallback()` to pass it to the handler registered before it. A request under `/v1/` therefore
meets the user stub, then the session stub, then the catch-all, which answers `501` with a message
naming the request — `{ message: 'The end-to-end stub has no handler for POST /v1/auth/login.' }`,
for example. No request under `/v1/` leaves the browser.

**A guarded screen, end to end.** `e2e/user-profile.spec.ts` seeds a `UserWireRecord` in
`beforeEach` and opens `/users/u_1` through its page object. The bundle boots, and the
`_authenticated` layout route's `beforeLoad` settles the session with `POST /v1/auth/refresh`;
`restoreSession` answers `200` with `{ accessToken: 'e2e.restored.access.token' }`, so the guard
admits the navigation ([Authenticated route guard](./route-guard.md)). The route's `loader`
prefetches the user query that the page's `useQuery` then joins, its `GET /v1/users/u_1` gets the
seeded record from the user stub, and the app validates, maps and renders it
([User profile (read path)](./user-profile.md)). Saving sends `PATCH /v1/users/u_1`: the stub
records the body, updates its stored record and answers `204`, so the refetch that the mutation's
invalidation triggers returns the new name ([Update user name (write path)](./update-user-name.md)).

**Assertions and artefacts.** Specs find elements by role, label and visible text through a _page
object_ — a module that owns one screen's locators and navigation — and assert with Playwright's
_web-first_ `expect`, which retries until the condition holds or its timeout expires. What reached
the wire is asserted on the stub (`userStub.namePatches()`), not read back from the DOM. The `list`
reporter prints progress and the `html` reporter writes `playwright-report/` without opening it; a
failed test keeps a screenshot and a video. On CI, where `CI` is set, a committed `test.only` fails
the run and a failing test is retried twice, its first retry recording a trace; the
`End-to-end tests` job then uploads `playwright-report/`.

Two failure paths matter:

- **A request no stub owns** reaches the catch-all, never the preview server — which inherits
  `server.proxy` from `vite.config.ts` and would forward `/v1` to `http://localhost:8000`, where a
  developer's real API may be listening. The app reads `501` as a server failure: the guard's
  refresh fails at once and the spec lands on `/sign-in`, a mutation fails at once, and a query is
  retried twice before its screen shows an error (see [Known limitations](#known-limitations)).
- **The app under test does not start.** A type error in any of the three TypeScript projects, a
  failed build or a busy port 4173 stops the web server, and Playwright runs no test;
  `stdout: 'pipe'` puts the build's output in the run log.

## Architecture

Feature-Sliced Design (FSD) splits `src/` into layers — `app`, `pages`, `widgets`, `features`,
`entities`, `shared` — each importing only from the layers below it
([Architecture boundaries](./architecture-boundaries.md)). The end-to-end suite belongs to none of
them: it observes the built app through a browser, meeting it only through the HTTP responses it
serves, the DOM it reads and one build-time variable. It may not import `src/`, and that fence is
mechanical: a `no-restricted-imports` block in `eslint.config.js` over `e2e/**/*.ts` and
`playwright.config.ts` rejects `@/**` and `**/src/**`, and `tsconfig.e2e.json` defines no `@/*`
path alias, so an aliased import also fails `npm run typecheck` with TS2307. Inside `e2e/` the
pieces mirror the app's own composition. Specs program against _seams_ — the repo's word, used
interchangeably with _port_, for a type a consumer depends on while the implementation is chosen
elsewhere: the extended `test` and its
`userStub` fixture, the `UserStub` interface and the `UserProfilePageObject` interface. The
concretes are stub handlers, each a `(route: Route) => Promise<void>` that fulfils the requests it
owns and falls back on the rest, and page-object factories. `e2e/fixtures/harness.ts` is the one
module that constructs the stubs and binds them to the page — the job the _composition root_,
`src/app/entrypoint/**`, does for the app ([Composition root](./composition-root.md)).
`e2e/fixtures/http-contract.ts` holds the shared vocabulary — the API prefix, the route pattern and
named statuses — and is the one `e2e/` module `playwright.config.ts` imports. Imports point one
way: specs → the harness, page objects, stub types and `http-contract.ts`; the harness → the stubs
and `http-contract.ts`; the stubs → `http-contract.ts`; nothing imports a spec.

## Public surface

### Commands

| Command                                        | What it does                                                                                                                                                                |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `npm run test:e2e`                             | `playwright test`: builds the app, previews it on port 4173 and runs every spec headless                                                                                    |
| `npm run test:e2e -- e2e/user-profile.spec.ts` | One spec file; npm passes everything after `--` to `playwright test`                                                                                                        |
| `npm run test:e2e -- -g "keyboard"`            | Only the tests whose title matches                                                                                                                                          |
| `npm run test:e2e -- --headed`                 | Shows the browser while the tests run                                                                                                                                       |
| `npm run test:e2e -- --trace on`               | Records a trace for every test — locally nothing else does, because traces are taken on a first retry and local runs never retry                                            |
| `npm run test:e2e:ui`                          | `playwright test --ui`: the interactive runner, for writing and debugging specs. It builds and starts the server once per session, so a change under `src/` needs a restart |
| `npm run test:e2e:report`                      | `playwright show-report`: opens the HTML report of the last run                                                                                                             |
| `npx playwright install chromium`              | Downloads the one browser the config uses; needed once per machine (CI adds `--with-deps` for the system libraries)                                                         |

### Layout and naming

```text
e2e/
├── app-shell.spec.ts
├── user-profile.spec.ts
├── fixtures/
│   ├── harness.ts
│   ├── http-contract.ts
│   ├── session-stub.ts
│   └── user-stub.ts
└── page-objects/
    └── user-profile-page-object.ts
```

- **Specs** are `e2e/**/*.spec.ts`, never co-located with source: the one sanctioned departure from
  the co-located `*.test.ts(x)` convention ([Unit and component testing](./unit-testing.md)). The
  suffix tells a reader that the file runs in a real browser against the built bundle rather than in
  jsdom; the directory is what keeps the runners apart. Playwright collects from `testDir: './e2e'`
  with its default `testMatch`, `**/*.@(spec|test).?(c|m)[jt]s?(x)`, and Vitest only from
  `src/**/*.{test,spec}.{ts,tsx}`. A helper under `e2e/` must therefore not end in `.spec.ts` or
  `.test.ts`, or Playwright runs it as a test file.
- **Stubs** are `e2e/fixtures/<resource>-stub.ts`, beside `harness.ts` and `http-contract.ts`.
- **Page objects** are `e2e/page-objects/<screen>-page-object.ts`, each exporting a
  `<Screen>PageObject` interface and a `create<Screen>PageObject(page)` factory — named so that
  neither the folder nor the symbol can be mistaken for the FSD `pages` layer.

### `e2e/fixtures/harness.ts`

| Export   | Contract                                                                                                                                                                                                                                                                                                               |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `test`   | Playwright's `test`, extended by `base.extend<{ userStub: UserStub }>`. The `userStub` fixture is test-scoped and `{ auto: true }`: before each test it registers `reportUnhandledRequest`, `restoreSession` and a fresh user stub's `handle` on `API_ROUTE_PATTERN`, in that order, and hands the test the `UserStub` |
| `expect` | Playwright's `expect`, re-exported so a spec needs a single import                                                                                                                                                                                                                                                     |

### `e2e/fixtures/http-contract.ts`

| Constant                 | Value                               | Used by                                                                                            |
| ------------------------ | ----------------------------------- | -------------------------------------------------------------------------------------------------- |
| `API_PREFIX`             | `'/v1'`                             | `webServer.env` in `playwright.config.ts`, `API_ROUTE_PATTERN`, `REFRESH_PATH` in the session stub |
| `API_ROUTE_PATTERN`      | `**/v1/**`, built from `API_PREFIX` | Every `page.route` registration in the harness                                                     |
| `OK_STATUS`              | `200`                               | The session and user stubs                                                                         |
| `NO_CONTENT_STATUS`      | `204`                               | The user stub, for a stored name update                                                            |
| `BAD_REQUEST_STATUS`     | `400`                               | The user stub, for a malformed `PATCH` body                                                        |
| `NOT_FOUND_STATUS`       | `404`                               | The user stub, for an id nobody seeded                                                             |
| `SERVER_ERROR_STATUS`    | `500`                               | `e2e/user-profile.spec.ts`, for the injected save failure                                          |
| `NOT_IMPLEMENTED_STATUS` | `501`                               | The harness's catch-all                                                                            |

### `e2e/fixtures/session-stub.ts`

`restoreSession(route: Route): Promise<void>` fulfils `POST /v1/auth/refresh` — `REFRESH_PATH`,
built from `API_PREFIX` — with `200` and `{ accessToken: 'e2e.restored.access.token' }`, and calls
`route.fallback()` for every other request. It has no per-test controls: every test that asks for a
session gets one.

### `e2e/fixtures/user-stub.ts`

`createUserStub(): UserStubRegistration` returns `{ stub, handle }`: `stub` is the `UserStub` the
fixture hands to specs, and `handle: (route: Route) => Promise<void>` is what the harness registers.
Each call owns its own records and history, and the fixture calls it once per test.

| `UserStub` member    | Signature                            | Behaviour                                                                                                                                                                |
| -------------------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `seed`               | `(record: UserWireRecord) => void`   | Stores the record under `record.id`, replacing any earlier one                                                                                                           |
| `failNextNameUpdate` | `(status: number) => void`           | The next well-formed `PATCH` for a seeded id is recorded, then answered with `status` and `{ message: 'The name update was rejected.' }` instead of stored; applies once |
| `namePatches`        | `() => readonly UserNameWirePatch[]` | A copy of every well-formed `PATCH` body received for a seeded id, in order, including one answered with an injected failure                                             |

What the handler answers, with `{id}` taken from the pathname by `USER_RESOURCE_PATTERN` and
URL-decoded:

| Request                         | Condition                                                   | Response                                                            |
| ------------------------------- | ----------------------------------------------------------- | ------------------------------------------------------------------- |
| `GET /v1/users/{id}`            | `{id}` was seeded                                           | `200` with the stored `UserWireRecord`                              |
| `GET` or `PATCH /v1/users/{id}` | `{id}` was not seeded                                       | `404` with `{ message: 'No such user.' }`                           |
| `PATCH /v1/users/{id}`          | The body is not `{ first_name: string, last_name: string }` | `400` with a message quoting the body received; nothing is recorded |
| `PATCH /v1/users/{id}`          | A failure was injected                                      | Recorded, then the injected status                                  |
| `PATCH /v1/users/{id}`          | Otherwise                                                   | Recorded; the stored `first_name` and `last_name` replaced; `204`   |
| Any other method or path        | —                                                           | `route.fallback()`                                                  |

The pinned wire types: `UserWireRecord` has `readonly` `id`, `first_name`, `last_name`, `email` and
`created_at` strings and a `role` of type `UserRoleWireValue` (`'ADMIN'`, `'MEMBER'` or
`'VIEWER'`); `UserNameWirePatch` has `readonly` `first_name` and `last_name` strings.

### The CI job

The `e2e` job in `.github/workflows/ci.yml`, named `End-to-end tests`, runs `npm run test:e2e`
against the production build on every push and pull request to `main`, skipped on the weekly
scheduled run like `Quality gates`. Its checkout, Node setup and place in the workflow follow the
same pattern as every job's; [Quality gates](./quality-gates.md#ci-workflow) owns the full step
table. What is specific to this job: installing Chromium with its system dependencies (`npx
playwright install --with-deps chromium`) happens on every run, since no step caches browsers, and
unless the run was cancelled it then uploads `playwright-report/` as the `playwright-report`
artifact — `if-no-files-found: ignore` covers a run that stopped before writing a report. It
declares no `needs`, so it runs in parallel with `Quality gates`.

## Configuration

The suite reads one environment variable, `CI`, and pins one app variable, `VITE_API_BASE_URL`.
Everything else is an option in `playwright.config.ts`, a setting of the CI job, or one of the two
`vite.config.ts` settings the harness relies on without owning.

| Variable / option                               | Default                                                         | Meaning                                                                                                                                                                                                                                                                  |
| ----------------------------------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `CI`                                            | Unset locally; set by GitHub Actions                            | Read through `node:process` into `isContinuousIntegration`, which switches `forbidOnly` and `retries`                                                                                                                                                                    |
| `VITE_API_BASE_URL` (`webServer.env`)           | `API_PREFIX`, i.e. `/v1`                                        | The API base URL baked into the bundle under test, set over the inherited environment so a shell export or an untracked `.env` cannot change it. `/v1` is also `appConfig`'s fallback and the `.env.example` value ([Configuration and environment](./configuration.md)) |
| `testDir`                                       | `'./e2e'`                                                       | Where Playwright collects specs, with its default `testMatch`                                                                                                                                                                                                            |
| `fullyParallel`                                 | `true`                                                          | Tests within one file run in parallel too, so each must stand alone                                                                                                                                                                                                      |
| `forbidOnly`                                    | `true` on CI, `false` locally                                   | A committed `test.only` fails the CI run                                                                                                                                                                                                                                 |
| `retries`                                       | `2` on CI, `0` locally                                          | A failing test is re-run; one that then passes is reported as flaky and does not fail the run, since `failOnFlakyTests` is not set                                                                                                                                       |
| `reporter`                                      | `[['list'], ['html', { open: 'never' }]]`                       | Progress in the terminal, plus an HTML report in `playwright-report/` that never opens by itself                                                                                                                                                                         |
| `use.baseURL`                                   | `PREVIEW_URL`, i.e. `http://localhost:4173`                     | What a relative `page.goto()` or `toHaveURL()` resolves against                                                                                                                                                                                                          |
| `use.locale`                                    | `'en-US'`                                                       | The browser language, which the i18n detector resolves to `en`                                                                                                                                                                                                           |
| `use.timezoneId`                                | `'UTC'`                                                         | The browser time zone, which `Intl` date formatting uses                                                                                                                                                                                                                 |
| `use.trace`                                     | `'on-first-retry'`                                              | A trace is recorded only on a test's first retry, so only on CI                                                                                                                                                                                                          |
| `use.screenshot`                                | `'only-on-failure'`                                             | A screenshot is kept for a failed test                                                                                                                                                                                                                                   |
| `use.video`                                     | `'retain-on-failure'`                                           | Video is recorded for every test and kept only for a failed one                                                                                                                                                                                                          |
| `projects`                                      | `[{ name: 'chromium', use: { ...devices['Desktop Chrome'] } }]` | The only browser                                                                                                                                                                                                                                                         |
| `webServer.command`                             | `npm run build && npm run preview -- --port 4173 --strictPort`  | Builds the production bundle, then serves it; `--strictPort` makes a busy port an error instead of a silent move to the next one                                                                                                                                         |
| `webServer.url`                                 | `PREVIEW_URL`                                                   | What Playwright polls before it starts the tests                                                                                                                                                                                                                         |
| `webServer.reuseExistingServer`                 | `false`                                                         | A server already listening on the URL is an error, not a shortcut                                                                                                                                                                                                        |
| `webServer.stdout`                              | `'pipe'`                                                        | The build and preview output appear in the run log; Playwright's default is `'ignore'`                                                                                                                                                                                   |
| `webServer.timeout`                             | `WEB_SERVER_TIMEOUT_MILLISECONDS`, i.e. `120_000`               | The budget for the build plus the server start; Playwright's default is 60 s                                                                                                                                                                                             |
| `PREVIEW_PORT`                                  | `4173`                                                          | The preview port — Vite's own default for `vite preview`, passed explicitly                                                                                                                                                                                              |
| `server.proxy` (`vite.config.ts`)               | `{ '/v1': 'http://localhost:8000' }`                            | Not set by the suite, but `vite preview` inherits it, so it is where an unanswered `/v1/` request would go; the catch-all keeps every such request in the browser                                                                                                        |
| `test.include` (`vite.config.ts`)               | `['src/**/*.{test,spec}.{ts,tsx}']`                             | Vitest's collection pattern, which keeps Vitest out of `e2e/`                                                                                                                                                                                                            |
| `timeout-minutes` (CI job `e2e`)                | `20`                                                            | GitHub Actions cancels the job after 20 minutes                                                                                                                                                                                                                          |
| `retention-days` (`playwright-report` artifact) | `7`                                                             | How long CI keeps the uploaded report                                                                                                                                                                                                                                    |

`tsconfig.e2e.json` is a standalone project with no `extends`. It includes `playwright.config.ts`
and `e2e`, loads `types: ["node"]` with `lib: ["ES2023", "DOM"]`, resolves modules as `bundler`
with `noEmit`, uses the same strictness flags as `tsconfig.app.json` (`strict`,
`noUncheckedIndexedAccess` and `exactOptionalPropertyTypes` among them), and declares no `paths`.
Its build info goes to `node_modules/.tmp/tsconfig.e2e.tsbuildinfo`.

## Usage & extension

### Run the suite

1. Install the browser once: `npx playwright install chromium` (on Linux, add `--with-deps`).
2. Make sure nothing listens on port 4173 — a running `npm run preview` makes the run fail rather
   than test that server.
3. Run `npm run test:e2e`. After a failure, `npm run test:e2e:report` opens the report with the
   failed test's screenshot and video; add `-- --trace on` to record traces locally.
4. Run it before opening a pull request. `npm run audit`, which the `pre-push` hook runs,
   type-checks, lints and format-checks `e2e/` but never runs it.

### Add a scenario to an existing screen

A scenario for the profile screen belongs in `e2e/user-profile.spec.ts`. Declare its record beside
`ADA`:

```ts
const GRACE: UserWireRecord = {
  id: 'u_2',
  first_name: 'Grace',
  last_name: 'Hopper',
  email: 'grace@example.test',
  role: 'VIEWER',
  created_at: '2024-03-09T12:00:00.000Z',
};
```

and add the test inside the `user profile` block:

```ts
test('renders a viewer role and its own join date', async ({ page, userStub }) => {
  const profile = createUserProfilePageObject(page);

  userStub.seed(GRACE);
  await profile.open(GRACE.id);

  await expect(profile.displayName()).toHaveText('Grace Hopper');
  await expect(profile.content()).toContainText('Viewer');
  await expect(profile.content()).toContainText('March 9, 2024');
});
```

The rules that scenario follows:

- **Import `test` and `expect` from `./fixtures/harness`.** The `test` from `@playwright/test` runs
  with no stubs and no catch-all.
- **Seed in the test or in `beforeEach`.** `fullyParallel` runs tests in any order, and each gets a
  fresh stub, so a test never relies on another's seed.
- **Seed what the app's schema accepts, not only what `UserWireRecord` allows.** `userDtoSchema`
  requires a valid email (`zm.email()`) and an ISO datetime with an offset
  (`zm.iso.datetime({ offset: true })`), so a type-correct seed such as `email: 'grace'` renders
  `This profile could not be loaded.` instead of failing to compile.
- **Find elements by role, label or visible text** — never a `data-testid`, a class or an id.
- **Assert what the user sees on the page and what reached the wire on the stub.**
- **Await every action and web-first assertion.** `@typescript-eslint/no-floating-promises` runs
  over `e2e/` too, so a forgotten `await` fails `npm run lint`.

### Worked example: cover sign-in

No spec covers sign-in yet (see [Known limitations](#known-limitations)). The five steps below add
that coverage and show every extension point at once: a status constant, a stub, a fixture, a page
object and a spec. None of these files exists yet; applied to `1c193c6`, they are clean under
Prettier, ESLint and `tsc`, and `npm run test:e2e` passes with them.

1. Name the new status in `e2e/fixtures/http-contract.ts`, beside the others:

   ```ts
   export const UNAUTHORIZED_STATUS = 401;
   ```

2. Pin the endpoint's wire shape and answer it in `e2e/fixtures/sign-in-stub.ts`. Like
   `user-stub.ts`, it owns one method and path, falls back on everything else, records what reached
   the wire and can fail its next request once:

   ```ts
   // SignInWireRequest is a pinned copy of the backend's POST /v1/auth/login contract — deliberately
   // NOT imported from src/entities/session/api/session-dto.ts. If the two disagree, one of them is
   // wrong, and finding that out is the entire purpose of this suite. Do not DRY this away.

   import type { Route } from '@playwright/test';

   import { API_PREFIX, BAD_REQUEST_STATUS, OK_STATUS } from './http-contract';

   export interface SignInWireRequest {
     readonly email: string;
     readonly password: string;
   }

   export interface SignInStub {
     readonly failNextSignIn: (status: number) => void;
     readonly signInRequests: () => readonly SignInWireRequest[];
   }

   export interface SignInStubRegistration {
     readonly stub: SignInStub;
     readonly handle: (route: Route) => Promise<void>;
   }

   const SIGN_IN_PATH = `${API_PREFIX}/auth/login`;
   const SIGN_IN_METHOD = 'POST';
   const ISSUED_ACCESS_TOKEN = 'e2e.issued.access.token';
   const REJECTED_MESSAGE = 'The sign-in was rejected.';

   function isSignInRequest(value: unknown): value is SignInWireRequest {
     if (typeof value !== 'object' || value === null) {
       return false;
     }

     const candidate = value as Partial<Record<keyof SignInWireRequest, unknown>>;

     return typeof candidate.email === 'string' && typeof candidate.password === 'string';
   }

   function readSignInRequest(rawBody: string | null): SignInWireRequest | undefined {
     if (rawBody === null) {
       return undefined;
     }

     try {
       const payload = JSON.parse(rawBody) as unknown;

       return isSignInRequest(payload) ? payload : undefined;
     } catch {
       return undefined;
     }
   }

   export function createSignInStub(): SignInStubRegistration {
     const receivedRequests: SignInWireRequest[] = [];
     let nextFailureStatus: number | undefined;

     const stub: SignInStub = {
       failNextSignIn: (status) => {
         nextFailureStatus = status;
       },
       signInRequests: () => [...receivedRequests],
     };

     async function handle(route: Route): Promise<void> {
       const request = route.request();
       const { pathname } = new URL(request.url());

       if (request.method() !== SIGN_IN_METHOD || pathname !== SIGN_IN_PATH) {
         await route.fallback();
         return;
       }

       const rawBody = request.postData();
       const signInRequest = readSignInRequest(rawBody);

       if (signInRequest === undefined) {
         await route.fulfill({
           status: BAD_REQUEST_STATUS,
           json: {
             message: `Expected a body of { email, password }, received: ${rawBody ?? 'no body'}.`,
           },
         });
         return;
       }

       receivedRequests.push(signInRequest);

       const failureStatus = nextFailureStatus;
       nextFailureStatus = undefined;

       if (failureStatus !== undefined) {
         await route.fulfill({ status: failureStatus, json: { message: REJECTED_MESSAGE } });
         return;
       }

       await route.fulfill({ status: OK_STATUS, json: { accessToken: ISSUED_ACCESS_TOKEN } });
     }

     return { stub, handle };
   }
   ```

3. Register it in `e2e/fixtures/harness.ts` as a fixture that a test asks for by name. Playwright
   sets up automatic fixtures before the fixtures a test names, so this `page.route` lands after the
   catch-all's and is tried before it. A stub that every test needs and no test controls, like
   `restoreSession`, goes into the `userStub` fixture instead, anywhere after the catch-all's line:

   ```ts
   import { test as base } from '@playwright/test';
   import type { Route } from '@playwright/test';

   import { API_ROUTE_PATTERN, NOT_IMPLEMENTED_STATUS } from './http-contract';
   import { restoreSession } from './session-stub';
   import { createSignInStub } from './sign-in-stub';
   import type { SignInStub } from './sign-in-stub';
   import { createUserStub } from './user-stub';
   import type { UserStub } from './user-stub';

   async function reportUnhandledRequest(route: Route): Promise<void> {
     const request = route.request();
     const { pathname } = new URL(request.url());

     await route.fulfill({
       status: NOT_IMPLEMENTED_STATUS,
       json: { message: `The end-to-end stub has no handler for ${request.method()} ${pathname}.` },
     });
   }

   export const test = base.extend<{ userStub: UserStub; signInStub: SignInStub }>({
     userStub: [
       async ({ page }, use) => {
         const { stub, handle } = createUserStub();

         // Playwright matches routes LIFO, so this registration order is load-bearing: the
         // catch-all must go in first to run last, or it answers 501 before the stubs are tried.
         await page.route(API_ROUTE_PATTERN, reportUnhandledRequest);
         await page.route(API_ROUTE_PATTERN, restoreSession);
         await page.route(API_ROUTE_PATTERN, handle);

         await use(stub);
       },
       { auto: true },
     ],
     signInStub: async ({ page }, use) => {
       const { stub, handle } = createSignInStub();

       await page.route(API_ROUTE_PATTERN, handle);

       await use(stub);
     },
   });

   export { expect } from '@playwright/test';
   ```

4. Add the screen's page object, `e2e/page-objects/sign-in-page-object.ts`, with its copy pinned
   from the `signIn` keys in `src/shared/i18n/locales/en/common.json`:

   ```ts
   import type { Locator, Page } from '@playwright/test';

   const COPY = {
     formName: 'Sign in',
     emailLabel: 'Email',
     passwordLabel: 'Password',
     submitButton: 'Sign in',
     rejected: 'Email or password is incorrect.',
   } as const;

   export interface SignInPageObject {
     readonly open: () => Promise<void>;
     readonly emailField: () => Locator;
     readonly passwordField: () => Locator;
     readonly submitButton: () => Locator;
     readonly rejectedNotice: () => Locator;
   }

   export function createSignInPageObject(page: Page): SignInPageObject {
     const form = () => page.getByRole('form', { name: COPY.formName });

     return {
       open: async () => {
         await page.goto('/sign-in');
       },
       emailField: () => form().getByLabel(COPY.emailLabel),
       passwordField: () => form().getByLabel(COPY.passwordLabel),
       submitButton: () => form().getByRole('button', { name: COPY.submitButton }),
       rejectedNotice: () => form().getByText(COPY.rejected),
     };
   }
   ```

5. Write `e2e/sign-in.spec.ts`, then run it alone with `npm run test:e2e -- e2e/sign-in.spec.ts`:

   ```ts
   import { expect, test } from './fixtures/harness';
   import { UNAUTHORIZED_STATUS } from './fixtures/http-contract';
   import { createSignInPageObject } from './page-objects/sign-in-page-object';

   test.describe('sign-in', () => {
     test('sends the normalized credentials and lands on the home page', async ({
       page,
       signInStub,
     }) => {
       const signIn = createSignInPageObject(page);

       await signIn.open();
       await signIn.emailField().fill('Ada@Example.test');
       await signIn.passwordField().fill('correct horse');
       await signIn.submitButton().click();

       await expect(page).toHaveURL('/');
       expect(signInStub.signInRequests()).toEqual([
         { email: 'ada@example.test', password: 'correct horse' },
       ]);
     });

     test('reports rejected credentials and stays on the form', async ({ page, signInStub }) => {
       const signIn = createSignInPageObject(page);

       signInStub.failNextSignIn(UNAUTHORIZED_STATUS);

       await signIn.open();
       await signIn.emailField().fill('ada@example.test');
       await signIn.passwordField().fill('wrong horse');
       await signIn.submitButton().click();

       await expect(signIn.rejectedNotice()).toBeVisible();
       await expect(page).toHaveURL('/sign-in');
     });
   });
   ```

The first scenario asserts what the app sent — `toNormalizedEmail` lower-cases the address before
it reaches the wire — and the second what it shows for a `401`; both behaviours belong to
[Sign-in](./sign-in.md).

### When the backend contract changes

The pinned copies change first, by hand:

1. Edit the wire type or literal in `e2e/fixtures/` — `UserWireRecord`, `UserNameWirePatch`, the
   `{ accessToken }` that `restoreSession` returns — and every seed built from it, such as `ADA` in
   `e2e/user-profile.spec.ts`. The suite now fails wherever the app still expects the old shape.
2. Change the DTO schema and the mapper under `src/entities/<entity>/api/`, with their unit tests
   ([User profile (read path)](./user-profile.md), [Session management](./session-management.md)).
3. Run `npm run test:e2e` until it is green. Never import the DTO into `e2e/` to keep the two in
   step: the duplication is the check.

### When copy or the API prefix changes

- A string from `src/shared/i18n/locales/en/*.json` that a spec reads changes in the same commit in
  the page object's `COPY`, or inline in `e2e/app-shell.spec.ts`.
- `API_PREFIX` moves the build pin, `API_ROUTE_PATTERN` and the refresh path together, but
  `USER_RESOURCE_PATTERN` in `e2e/fixtures/user-stub.ts` spells `/v1` itself and must be changed
  with it (see [Known limitations](#known-limitations)).

## Design decisions & trade-offs

- **Playwright, not Cypress or WebdriverIO.** The commit that introduced the harness (`5f69818`)
  records why: Cypress's in-browser runner cannot cleanly intercept the initial document request and
  its parallelism is a paid feature, and WebdriverIO asks for heavier configuration for no gain at
  this scale. The config leans on what Playwright ships: a `webServer` that builds and serves the
  app, `page.route` at the browser's network layer, parallel workers, device profiles, and
  screenshots, video and traces gathered into one HTML report.
- **It tests the build, not the dev server.** The gap the suite closes is that the built bundle was
  unverified, so what it drives is exactly what `vite build` emits: minified, with `import.meta.env`
  inlined, with both devtools panels absent — `ReactQueryDevtools` and `TanStackRouterDevtools`
  render `null` when `NODE_ENV` is not `development` — and with the route tree the router plugin
  generates. `vite.config.ts` loads that plugin only outside `test` mode, so Vitest never runs it.
  The price is a full `tsc -b && vite build` before the first test of every run.
- **A fresh server on every run.** `reuseExistingServer` is `false` — not the `!process.env.CI`
  that Playwright's own documentation suggests — and `vite preview` gets `--strictPort`, because
  reusing whatever answers on port 4173, such as an `npm run preview` of an older build, would test
  the wrong bundle. The cost is a rebuild per run and a port that must be free;
  `npm run test:e2e:ui` builds once per session for a faster loop while writing a spec.
- **The build is hermetic.** Vite loads `.env` files during `build` but lets a real `process.env`
  `VITE_*` variable win over them, and Playwright merges `webServer.env` over the environment it
  inherits, so the pin beats both a shell export and an untracked `.env`
  ([Configuration and environment](./configuration.md)). Without it, a developer's
  own `VITE_API_BASE_URL` would send the bundle's requests past `**/v1/**`, and the verdict would
  depend on that developer's machine. One constant, `API_PREFIX`, feeds the pin, the route pattern
  and the refresh path, so they cannot drift apart — with one exception, listed under
  [Known limitations](#known-limitations).
- **The browser is pinned to one language and one time zone.** The i18n detector reads `?lng=`,
  then `localStorage` (`app.locale`), then the browser language; a fresh context has no stored
  locale, so `locale: 'en-US'` selects `en`, the language the specs' copy is written in, where a
  machine set to Russian would otherwise render `ru`
  ([Internationalization](./internationalization.md)). `UserProfileView` formats dates in the
  browser's time zone, and a `created_at` of
  `2024-01-05T12:00:00.000Z` reads January 5, 2024 in UTC but January 6, 2024 in
  `Pacific/Auckland`. The cost is that no spec exercises another locale or zone.
- **The network is stubbed in the browser, not in the app.** `page.route` intercepts inside
  Chromium, so the bundle under test contains no mocking code and `src/main.tsx` needs no test
  branch. MSW was the alternative and was rejected for that reason: its browser mode has to be
  started from application code (`setupWorker(handlers).start()` before the app mounts) and serves
  `mockServiceWorker.js` from `public/`, which `vite build` copies into `dist/`. MSW stays where it
  fits, in the Vitest suite through `msw/node` ([Unit and component testing](./unit-testing.md)).
- **Handlers run last-registered-first, so the catch-all goes in first.** Playwright offers a
  request to the most recent matching `page.route` handler, and `route.fallback()` passes it to the
  one registered before. Registered last, the catch-all would answer `501` before any stub was
  tried; the only comment in `harness.ts` guards that order. Every stub fulfils only what it owns
  and falls back on the rest, so a new resource is a new file plus one registration, with no edit to
  an existing stub, and the order among stubs does not matter.
- **The catch-all answers `501` and keeps every request in the browser.** Without it, an unowned
  request would reach `vite preview`, which inherits `server.proxy` from `vite.config.ts` and
  forwards `/v1` to `http://localhost:8000` — a developer's real API, or a proxy error. `501` is a
  status no stub answers on purpose: the stubs use `200`, `204`, `400` and `404`, and a spec
  injects `500`, so a `501` can only mean a missing handler, and its body names the method and path.
  It does not make that failure fast, though; see [Known limitations](#known-limitations).
- **The user stub is a small state machine, not a canned response.** It seeds records, applies a
  successful `PATCH` so the refetch after invalidation returns the new name, keeps every well-formed
  body for assertion, and fails the next update on request. A canned response would keep answering
  the old name, so the save scenario could never see the new heading; `namePatches()` pins the exact
  snake_case body at the wire, which is how the trimming scenario checks `first_name: 'Augusta'`;
  and a malformed body gets a `400` that quotes it instead of a silent success.
- **Every wire shape is pinned in the suite, never shared.** `user-stub.ts` declares
  `UserWireRecord` and `session-stub.ts` answers with a literal `{ accessToken }`, each under a
  header that forbids importing the DTO it duplicates. A shared declaration would make a wire-field
  rename update both sides at once and keep the suite green while production broke; one declaration
  cannot detect its own drift. The ESLint block rejects both `@/entities/user` and
  `../../src/entities/user/api/user-dto`, and the missing `@/*` alias makes the first fail with
  TS2307 as well. A relative import still type-checks — TypeScript follows an import to a file
  outside `include` — which is why the lint rule is the fence for that form.
- **Copy is pinned the same way.** The page object's `COPY` repeats strings from `common.json`
  rather than importing the locale file, which the fence forbids anyway. The suite asserts what a
  user reads, so a copy change fails it until the page object follows.
- **Locators follow the accessibility tree, and a page object appears at the second call site.**
  Elements are found by role, label or visible text, never by `data-testid`, class or id. The ids
  are generated: `TextField` derives its control id from React's `useId()` (through
  `useFieldReveal` and `useFieldAria`), and the name form takes its accessible name from a heading
  whose id also comes from `useId()`, so the label and name associations are the stable contract —
  and the ones assistive technology relies on. Scoping lookups to the form named `Update name`
  keeps a label from matching elsewhere on the page. Strings move into a page object once a second
  call site appears: `'Save name'` is used by five scenarios and `'First name'` by four, while
  `e2e/app-shell.spec.ts` uses `'Page not found'` and `'Back to home'` once each and keeps them
  inline. The page object finds and navigates; assertions stay in the spec. `TextField`'s
  generated ids belong to the form seam ([Forms](./forms.md)).
- **Every test gets a restorable session.** `restoreSession` is registered for every test and always
  issues a token, but it fires only when something asks for a session — today the seven profile
  scenarios, whose route sits behind the guard
  ([Authenticated route guard](./route-guard.md)); `e2e/app-shell.spec.ts` visits only unguarded
  paths. One unconditional stub keeps guarded specs free of session setup; the cost is that only the
  guard's admit path is covered.
- **The fence is automatic.** `{ auto: true }` installs the catch-all and both stubs for every test,
  including the one in `e2e/app-shell.spec.ts`, which names only `page`, so no spec can forget
  them. The fixture is named after the one stub specs control, not after everything it installs.
- **Outside `npm run audit`, inside CI.** `audit` is what the `pre-push` hook runs and must stay
  fast; a gate that builds the app and boots a browser belongs in CI, as the `End-to-end tests` job
  running in parallel with `Quality gates`, so a pull request gets both signals at once. The suite's
  code is still gated on every push: `tsc -b`, inside both `npm run typecheck` and `npm run build`,
  checks the end-to-end project, and `eslint .` and `prettier --check .` cover `e2e/`
  ([Quality gates](./quality-gates.md)).
- **Artefacts when they help, not on every run.** A failed test keeps a screenshot and a video, and
  a trace is taken on the first retry, which only CI performs; the HTML report gathers all three,
  and CI uploads it even from a failed run. Retries absorb a one-off failure on CI, at the cost that
  a test that passes on retry is only marked flaky in the report.
- **Output folders are ignored in three places, and the report's entries are load-bearing.**
  `test-results`, `playwright-report` and `blob-report` are listed in `.gitignore`,
  `.prettierignore` and ESLint's `ignores`. The HTML report is a minified, roughly half-megabyte
  HTML file that `prettier --check .` rejects, and a recorded trace copies the trace viewer's
  JavaScript into `playwright-report/trace/`; those files belong to no TypeScript project, so typed
  linting fails each one with "was not found by the project service". Without the `playwright-report`
  entries in `.prettierignore` and ESLint's `ignores`, either failure would break `npm run audit`,
  and with it every push, until the folder was deleted. `playwright/.cache` is also listed in
  `.gitignore` and `.prettierignore`.

`npx vitest run <path>` for one file — is described in

## Known limitations

- **No sign-in spec.** `e2e/` holds `app-shell.spec.ts` and `user-profile.spec.ts`; neither visits
  `/sign-in`, and no stub answers `POST /v1/auth/login`, so a sign-in attempted in the browser suite
  today meets the catch-all's `501` and shows `Sign-in is unavailable right now. Try again.`
  [Worked example: cover sign-in](#worked-example-cover-sign-in) is what covering it takes.
- **The guard's redirect path is not covered end to end.** `restoreSession` always issues a token
  and the user stub never reads the `Authorization` header, so the seven profile scenarios pass the
  guard as a signed-in visitor; with the guard's `beforeLoad` removed, all eight scenarios still
  pass (checked against `1c193c6`). The redirect to `/sign-in` for an `anonymous` or `unknown`
  session, and the `401` → refresh → replay path, are covered only in Vitest
  ([Authenticated route guard](./route-guard.md), [Session management](./session-management.md),
  [HTTP transport](./http-transport.md)).
  Covering them needs a session stub that a test can control, built like the `signInStub` fixture
  in the worked example.
- **The catch-all's `501` is retried like any server error.** `toHttpErrorFromAxios` classifies
  every status of 500 or above as `server`, and `createQueryClient` retries `server` failures up to
  `MAX_QUERY_RETRIES` (2) times, with TanStack's default back-off of 1 s and then 2 s
  ([HTTP transport](./http-transport.md)). A query that meets the catch-all is therefore sent three
  times — measured at about 0 s, 1 s and 3 s — before its screen shows an error, while the guard's
  refresh and mutations fail at once. This contradicts the rationale in `5f69818`, which chose `501`
  because it "is classified as a client error and surfaces immediately"; the classification was the
  same when that commit landed.
- **The pinned copies catch drift in one direction only.** They catch the app tightening away from
  the wire — a renamed or retyped field. They do not catch the wire loosening away from the app: if
  the server makes a field optional, the pinned copy keeps sending the old shape and nothing fails.
  That needs a contract artefact generated from the server, such as OpenAPI or Pact.
- **`USER_RESOURCE_PATTERN` hard-codes the prefix.** It is `/^\/v1\/users\/(?<userId>[^/]+)$/u`
  rather than a pattern built from `API_PREFIX`, so changing `API_PREFIX` alone moves the build, the
  route pattern and the refresh path, and every user request then falls through to the catch-all.
- **Nothing enforces importing from the harness.** The ESLint block for `e2e/**` restricts only
  `@/**` and `**/src/**`. A spec that imports `test` from `@playwright/test` compiles, lints and
  runs with no stubs and no catch-all, and its `/v1/` requests reach `vite preview` and its proxy.
- **Chromium only.** The one project, `chromium`, uses `devices['Desktop Chrome']`, and CI installs
  only Chromium; Firefox, WebKit and mobile viewports are not exercised.
- **A flaky test does not fail CI.** With `retries: 2` and no `failOnFlakyTests`, a test that fails
  and then passes is reported as flaky, and the job stays green; only the uploaded report shows it.
- **Nothing in the repository makes the job blocking.** The `End-to-end tests` job runs on every
  pull request, but whether its failure blocks a merge is a required-status-check setting on GitHub,
  outside the repository ([Quality gates](./quality-gates.md)).
